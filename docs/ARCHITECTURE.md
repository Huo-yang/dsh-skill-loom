# Skill Loom 架构

## 角色和能力族

角色是会话可绑定的技能依赖图。角色有显示名、可选简介、人设、技能集合与依赖边。边的存储方向为 from → to，含义是 from 需要 to。画布把前置技能画在上方，使用它的技能画在下方。

能力族是可重复插入的技能子图。预览使用虚拟根。插入时，把虚拟根下的技能接到目标节点。目标是角色根时直接纳入技能，目标是技能时追加对应依赖。合并会共享同名技能，保留已有边，补齐缺失依赖。会形成环的图无法保存。

## 健康和会话

graph.js 检查可解析技能和依赖闭包。找不到的技能为红，依赖红色或灰色技能的节点为灰。健康节点进入运行时集合。技能锚点记录保存时的来源，供解释缺失与漂移。

runtime.js 在绑定 Agent 的作用域内，把其余技能注册为不可调用的同名覆盖项，从该会话的技能目录排除，并安装角色的人设段。解绑时撤销这些注册。文件、命令与网络权限由 DSH 管理。其他 Agent 的技能目录独立。

catalog.js 汇总全局和活跃作用域的技能供编排。运行时按目标 Agent 的实际技能计算健康。技能注册变化时，宿主防抖刷新现有绑定。

## 草稿、存储和接口

- client.js 提供 Web 主页面与会话右侧页签。图编辑、撤销和重做先在草稿上进行。浏览器存储只保存未提交的草稿，刷新可恢复。
- http.js 提供 /skill-loom 下的角色、能力族、绑定和检查请求接口。角色图预览使用正式保存路径的校验和规划逻辑。保存带 revision，冲突时保留浏览器草稿。
- store.js 以临时文件加原子重命名保存对象。默认数据根为 $DSH_HOME/roles，未设置 DSH_HOME 时使用 ~/.dsh/roles。角色保存在此目录，能力族位于 families 子目录，会话绑定在 bindings.json。
- index.js 挂载 DSH 服务、串行化写操作并刷新已绑定的 Agent。宿主的角色版本历史保存在内存。

## DSH 自助编排

role_graph 创建、检查和修改角色，可绑定当前会话。role_family 创建、修改或把能力族合入角色。role_spawn 用指定角色运行子 Agent。role_review 把已保存的检查目标交给当前 Web 会话，客户端通过 DSH 右侧栏服务打开对应依赖图。

预置能力族「技能编排助手」由编排和检查技能组成。技能通过宿主全局注册，仍受会话角色的技能可用性规则约束。

## 技能退役与写入一致性（0.1.5）

retirement.js 为 Web 和 DSH 注册工具提供同一个引用盘点和退役服务。技能以精确名称跨作用域标识，已保存角色／能力族的成员、边端点和 conflicts 均计入；内置管理技能受保护。目录发现未知、未解析、已知文件缺失与持久化退役是不同状态。已保存 anchors 与已知名字保留，清理后消失的技能仍可检查。读取与提议不写文件，退役不会删除 SKILL.md、卸载提供者或修改 DSH 权限。

宿主写入队列外还有角色目录锁，所有受保护的图保存／删除和退役／恢复在锁内复查。历史恢复成功后才消费栈。新引用退役名字的写入被拒绝，包括复制、能力族应用与撤销／重做。外部文件编辑和旧版无锁写入不在保证范围。

图与元数据跨文件保存前写入 `.skill-loom-pending-write.json`，包含旧图及预期元数据；完成两者后才清除。若部分失败或崩溃遗留标记，公开读取与后续写入均拒绝，不能误判依赖已经清理。普通失败仅在图字节确认未变时清除标记。锁和标记不自动抢占／修复；必须核对实际文件后人工处理。该机制不承诺跨文件原子性或断电持久性。

role_graph create 的可选 description 与 set_description 采用相同的空白规范化和 160 字符限制，省略时不生成内容。role_family delete 仅接受精确 ID、confirm=true 和调用方提供的当前正整数 revision，复用 Web 的 families.change，保留已复制到角色的图。模型清理先查看 plan/propose 的待移除边及冲突约束，确认后使用所查看的版本保存，再单独确认退役。

这里的工具是 DSH 原生注册工具。0.2.2-rc.5 的隔离 Web 宿主验证覆盖真实 defineTool 包装和注册入口；未发现／验证向外暴露 Loom 的 MCP JSON-RPC 服务，不应把这项结果称为外部 MCP 端到端验证。

### 未完成写入的保守恢复

这不是自动修复入口。先停止使用该 rolesDir 的所有 Loom/DSH 进程，确认没有写者；保留目录、待处理标记及实际图／元数据文件的备份，不把包含用户图的标记上传到公共位置。核对标记的 `graphFile` 确实是这个目录中预期的角色／能力族文件，检查实际文件与标记是否有外部编辑差异；有差异或标记缺字段时停止，由操作者核对，不能只清标记。

可选择保守回滚：将 `previousGraph` 的原始字符串字节恢复到对应图，将 `previousMetadata` 的原始字符串字节恢复到 `skill-retirement.json`。值为 null 表示写入前不存在该文件；先保存当前文件备份，再恢复“原先不存在”的状态。保留 `intendedMetadata` 和部分写入文件备份，避免丢弃失败操作中的信息。回读确认与记录的旧字节完全相同后，最后移走 pending 标记到备份位置；若存在崩溃遗留锁，在确认无写者且恢复完成后再人工处理。不要在运行中的宿主上执行这些操作。

重新启动后，旧图中的引用仍会阻止退役。重新检查、确认并保存清理，再用新快照单独确认退役。合成数据回归覆盖只有最后一个引用的缺失技能：元数据失败后重建整个插件，Web 与注册工具均拒绝；按上述原字节回滚后引用恢复并阻止退役；再次清理保存及重启后，已知缺失项仍可显式退役。若恢复步骤再次失败，保留标记和备份，继续阻断，不把恢复描述为成功。
